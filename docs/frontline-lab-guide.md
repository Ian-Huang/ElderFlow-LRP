# 現場工具箱與實驗室 (Frontline Lab / Toolkit) 開發規範與 AI 協作手冊

本文件為長照機構新系統中**「現場工具箱與實驗室（Frontline Lab / Toolkit）」**的核心架構設計契約與 AI 協作規範。未來所有接手本專案的工程師與 AI Agent，**在協助機構第一線現場人員（包含護理師、照服員、社工師、復健治療師、行政總務、機構主任等領域專家）開發或調整自製功能時，必須嚴格遵循本手冊**。

---

## 一、模組定位與設計初衷

長照機構第一線同仁是系統最核心的使用者與領域專家（Domain Experts）。過去外包工程師常因缺乏現場臨床與行政經驗，溝通成本極高且修改難以到位，導致現場人員必須使用 Google 試算表、Apps Script 勉強拼湊以應對評鑑與日常管理。

新系統開闢統一的**「現場工具箱與實驗室」**專區（位於 `apps/web/src/pages/frontline-lab/`，單一入口 `/frontline-lab`），定位為：
1. **全院現場孵化器（Pragmatic Incubator）**：護理、照護、社工、總務、行政主管皆能透過 AI 迅速建立所需表單。
2. **零阻力動態資料庫（Schema-less by Default）**：不需等待工程師開資料表或寫 SQL migration，像試算表一樣隨意增減欄位，資料直接保存在系統內（本機 IndexedDB + 雲端 D1）。
3. **三合一閉環驗證（3-in-1 Studio）**：在同一個畫面上直接完成「公開手機端填寫 ➔ 內部資料庫編修 ➔ A4 評鑑報表滿版列印」。
4. **與主系統架構嚴格隔離**：現場工具的實驗與調整完全不影響主系統核心代碼，待現場使用成熟後再由工程師平滑升格。

## 三、AI Agent 自動邊界守則（重要：AI 自行守門，不需現場同仁提醒）

當使用者在對話中提及**「工具箱」、「現場工具箱」、「實驗室」**，或提及具體模組（如**「訪客登記」、「修繕表」、「消毒表」、「品質指標」**）時，AI 必須自動遵循以下原則：

### 1. 綠燈區（允許主動新增與修改）
* `apps/web/src/pages/frontline-lab/**`（所有現場工具、評鑑專用報表 `reports/` 與三合一工作台）
* `apps/web/src/hooks/useSandboxCollection.ts`（動態儲存封裝）

### 2. 紅燈區（嚴禁未獲核心工程指示擅自修改）
* 嚴格禁止改動 `packages/core/**`（核心領域模型）
* 嚴格禁止改動 `apps/web/src/repositories/**`（正式 Repository 抽象層）
* 嚴格禁止修改資料庫遷移腳本（Migrations）、Vite/TypeScript 編譯設定、CI/CD 流程

### 3. 黃金業務防呆準則（臨床與評鑑血淚規範）
1. **電話與編號零保護**：電話號碼開頭的 `0`（如 `0975...`）與床號（如 `2-3`）必須以純字串保存，禁止自動轉為數字或日期。
2. **未來日期嚴禁預打勾（評鑑大忌）**：未發生的未來日期絕對不可預先打勾或簽章，前端必須予以阻擋。
3. **列印隔離（No-Print Isolation）**：除 A4 紙張本體外，所有網頁外殼、導覽列、Tab 切換鈕必須加上 `no-print`，並注入 `@page` 規格，嚴禁網頁按鈕印到報表上造成跨頁跑版。

## 四、專區 B「現場自製登記工具（三件套）」通用標準與規範

專區 B 的所有現場自製工具（例如「訪客與志工登記」、「住民活動簽到」、「耗材領用」等），統一必須遵循**「三件套閉環通用架構」**：

```
┌─────────────────┐       ┌─────────────────┐       ┌─────────────────┐
│ 1. 手機填寫端   │ ────> │ 2. 內部資料庫   │ ────> │ 3. A4 報表列印  │
│ (Mobile Kiosk)  │       │ (DataGrid)      │       │ (Audit Print)   │
└─────────────────┘       └─────────────────┘       └─────────────────┘
```

### 1. 模組通用實作規範
* **手機填寫端 (Mobile Kiosk)**：
  - 支援 QR Code 掃碼直開、無痛免登入。
  - 依照使用者身分（如家屬、志工、廠商）條件式展開專屬欄位。
  - 離線友善：斷網時能本機暫存，上線時自動同步推送至雲端 D1。
* **內部資料庫 (DataGrid - Excel/試算表操作體驗)**：
  - **全模組統一採用 `<FrontlineDataGrid<T> />` 通用元件**（位於 `apps/web/src/pages/frontline-lab/components/FrontlineDataGrid.tsx`）。
  - **試算表直覺操作**：支援單元格雙擊（Double-click）原地行內編輯，按 Enter 立即持久化並同步至 D1。
  - **批次處理**：支援勾選多選（Row Selection）、全選、一鍵批次刪除。
  - **貼上匯入器（Clipboard Importer）**：現場人員從 Google Sheet / Excel 複製多列多欄後，在系統點擊「📋 貼上試算表匯入」，貼上 Tab 分隔文字，系統自動辨識表頭與預覽，一鍵 `insertMany` 批次寫入本機與 D1。
  - **欄位動態可見性**：支援自訂下拉勾選顯示/隱藏特定欄位，避免欄位過多造成畫面擁擠。
  - **CSV / Excel 匯出**：內建一鍵匯出 CSV 功能。
* **A4 評鑑列印端 (Audit Print View)**：
  - 套用機構標準公文與評鑑樣式（`a4-sheet a4-landscape` 或 `a4-portrait`），黑白實線邊框。
  - 評鑑親簽欄位依規定維持空白供醫護人員手寫簽章。
  - 嚴格注入 `@page` 邊距與 `no-print` 樣式。

### 2. 跨模組欄位動態演進守門則 (Triad Consistency Guardrail)
當現場人員要求**「在手機登記端增加或刪除某個欄位」**時，AI 與工程師**必須主動守護三件套的一致性與向後相容**，不需現場人員額外提醒：
1. **Schema-less 向後相容**：
   - 資料介面（Interface）中的新欄位一律宣告為可選型別（如 `residentBed?: string`）。
   - 舊資料缺少該欄位時，系統絕不可 crash 或出現 `undefined`。
2. **DataGrid 即時反應**：
   - 新增欄位必須配置於 `<FrontlineDataGrid />` 的 `columns` 定義中。
   - 若新增欄位屬於非高頻次欄位，預設設為 `defaultVisible: false`，現場人員可由「欄位顯示」選單自行開關。
3. **A4 評鑑報表優雅 Fallback**：
   - 報表列印端在呈現該欄位時，必須給予標準空值容錯（如 `{rec.residentBed || '—'}`），維持版面排版整齊不移位。
4. **貼上匯入器欄位映射相容**：
   - 匯入器支援舊版與新版 Excel 格式，即使匯入的剪貼簿資料缺少新欄位亦能自動安全補空。
